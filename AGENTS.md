# AGENTS.md

**Phosphene**: a logo-animation film generator (the name since 2026-10-26; it was "Demo Studio", and it is meant to go beyond the Demo logo). 9:16 match-cut films where every shot places the brand's mark at the same place and size, in a different material/scene. **Projects** (one per mark, `studio/projects.py`): Demo ("demo") is the first, its circular orbital logo at exact dead-center (50%, 50%), 18% of frame width.

## Projects (studio/projects.py)
A project is a folder `projects/<slug>/` with a `project.json`: name, the mark (`mark.png`, any shape: the page draws an SVG or any image into a PNG trimmed to the mark before sending it), `mark_size` (% of the width), `mark_x` / `mark_y` (% across / down), `mark_shape` and `mark_noun` (how the prompts describe it), `brief` (who it is for, one line: it replaces "Demo, a creative toolkit for creatives at an agency group" in the quality bar), `palette` (hex), and where its plates, curation, caches and guide images live (`paths`; by default all inside its folder). New projects are gitignored (`projects/*`, they stay on the machine that made them); `projects/demo/project.json` is committed and points at DEMO's old places (assets/ai-plates, studio/curation_state.json, assets/logo-guides, ...), so nothing of DEMO moved. The server works on one project at a time: the open one is remembered in `studio/.local.json` (gitignored); `apply_project` points `PLATES_DIR`, `CURATION_FILE`, `QA_CACHE_FILE`, `THUMBS_DIR` and the features cache at it (`/api/projects`: list, switch, create, update; refused with 409 while something runs; the page reloads after a switch). Everything brand-specific reads the project: the prompt sentence (`build_full_prompt`, `mark_words`: for DEMO exactly the old words, a test guards them), the quality bar (`quality_bar`), world invention, softening and the critic's rubric, DEMO's colours in the worlds and colour ideas mapped to the project's palette (`projects.rebrand`, DEMO unchanged), the Krea guide (made from the mark at its size and place: cream on near-black and ink on cream, `make_guides`; uploaded once, `guide_cache_file`, forgotten when the mark changes), the logo check (`qa_engine.mark_spec`: the project's mark at its size and place; DEMO keeps `DEMO_MARK`, its orbital mask; a test showed it gives identical results on 40 real plates), the logo target in the page (`--mark-w/x/y/ar`, `showProject`: the mark's box), full-size plates (`/api/plate`) and the export's name. DEMO is fixed (its mark, size and place; "Project settings…" is off for it): another DEMO with other settings is a new project. Where things live: `studio/places.py` (the repo's places, or with `PHOSPHENE_HOME` / `PHOSPHENE_SUPPORT` / `PHOSPHENE_WEB` / `PHOSPHENE_FFMPEG` the Mac app's: projects in ~/Documents/Phosphene, this machine's files (keys, the Krea sign-in, the log, exports) in ~/Library/Application Support/Phosphene). The app's sample, Demo, is copied into the projects once on first launch (`seed_examples`, a marker in the support folder; never over an existing folder; back only when no project is left at all). **Export project…** (`export_zip`: NAME.phos, one zip with the project's folder: project.json without paths, mark, guides, state.json with the groups, snapshots, order and trash, every image; never the Kimi key; downloaded once through `/api/download-zip`) and **Import project…** (`import_zip`: always a new project, only a project's files, nothing outside its folder; then it opens). A new project starts with the mark (the first field; everything else and Create are off until it is read, `formStage` pick / reading / ready; Cancel always works and drops the answer): it is read (`/api/describe-mark`): its own colours from its pixels (`mark_colours`) and Kimi's name for it, a line on the brand, its shape and what to call it and colours to go with it (`describe_mark`, one try of at most 60 s); a spinner and the seconds show while Kimi reads; then everything can be changed (never written over what was typed). The preview's ground is mid grey so a black mark and a white one both show, and the mark has the logo target's dashed box around it, as every image will. Opening another project shows a cover (`cover`), then the loader names it. Curate's **Download** (`downloadShown`, `/api/download-zip`) zips the images shown (All or the group), full size, in order; not in the Trash. Header: the project's mark and name, a menu to switch, New project…, Project settings…, Export project…, Import project… (the form `#projectModal`: name, mark, size, across, down, its shape, called, brand, colours, with a 9:16 preview).


## Layout
- `studio/server.py` — the API server (port 8765, `PORT` env to change): JSON API, plates and exported video. It also serves the built page from `studio/web/dist` if `npm run build` was run.
- `studio/web/` — the frontend (Vite, vanilla JS): `index.html` (markup), `src/app.js`, `src/style.css`, `vite.config.js` (proxies `/api`, `/assets`, `/outputs` to :8765). Inline `onclick=` handlers need the function exported at the bottom of `app.js` (a test checks this).
- `studio/krea_mcp_client.py` — Krea image generation over MCP (`https://api.krea.ai/mcp`). The app signs in to Krea itself, as an MCP client (OAuth 2.1: dynamic client registration, PKCE; Settings › Connect Krea opens Krea's sign-in in a tab (in the app, the usual browser: the opener's capability allows only krea.ai URLs; with no URL scope every link was refused), Krea sends it back to `/api/krea-callback`; once connected the one button is Sign out of Krea; `start_login` / `finish_login` / `forget_login`); the client and its tokens live in `studio/.krea_auth.json` (gitignored, 0600, one sign-in per machine); the access token is refreshed before it expires and after a 401. Opencode is not used any more.
- `studio/qa_engine.py` — logo QA on generated plates (needs `demo-info/design-system/logo-cream.png`). `demo-info/` also holds the design-system PDFs and the playbook: reference, not read by code.
- `studio/chapters.py` (territories), `diversity.py` (random axes), `taste.py` (learning from kept/trashed), `critic.py` (optional AI scoring, off by default), `web/src/drone.js` (the synthesized drone, WebAudio), `sequences.py` (Manual/AI orders), `editor.py` + `features.py` (AI ordering), `bench.py` (scripted generation runs, optional).
- `studio/gen_log.py` — the written record of what the server did (`studio/generation_log.jsonl`, gitignored, rotates at 5 MB): server starts, Kimi batches, every image (all retries, logo check, seconds), AI orders, exports, deletions. Read it with `npm run log` (or `python3 studio/gen_log.py --failures`), or `GET /api/log`. An `image_start` with no result followed by a `server_start` means a restart cut the image short.
- `studio/curation_state.json` — DEMO's approvals, trash, order, titles, prompts, per-plate model. Committed on purpose: it is the selection history (other projects keep theirs in `projects/<slug>/state.json`).
- `assets/ai-plates/` — generated plates (committed). `outputs/*.mp4` is gitignored.

## Run
`README.md` is the guide for someone setting it up on their own computer (a colleague): `npm run setup` (`scripts/setup.sh`: checks Python 3.10+, Node 20+, ffmpeg and git-lfs, offers `brew install` for what is missing, `git lfs pull`, `.venv` + pip, `npm install`; safe to run again), then Settings › Connect Krea and the Kimi key (Generate opens Settings on whichever is missing). ffmpeg is found on PATH or Homebrew's places (`find_tool`).
```fish
npm install        # once
npm run dev        # API with auto-restart (studio/dev.py) + Vite with hot reload -> http://localhost:5173
```
Separately: `npm run api` (backend only, restarts when `studio/*.py` changes, the page reloads itself) and `npm run web` (Vite only). `npm run build` writes `studio/web/dist` and the backend then serves the page at :8765. Needs Python 3 with Pillow (`pip3 install -r requirements.txt`), ffmpeg at `/opt/homebrew/bin/ffmpeg`, Node 20+. The user runs these themselves; do not start or kill their server unless asked. Do not restart the API mid-generation.

## The Mac app (app/, branch native-app)
Phosphene.app (Tauri 2, `app/src-tauri`): a native window (macOS's WebKit) around the same page and server. `src/main.rs` starts the bundled server (`studio/server.py` frozen with PyInstaller) on a free local port with `PHOSPHENE_HOME` = ~/Documents/Phosphene (the projects: visible in Finder, backed up, never touched by updates or by deleting the app), `PHOSPHENE_SUPPORT` = ~/Library/Application Support/Phosphene (keys, the Krea sign-in, the log, `server.log`, exports), `PHOSPHENE_WEB` / `PHOSPHENE_FFMPEG` / `PHOSPHENE_EXAMPLES` (inside the app); shows `app/splash` ("Starting Phosphene…", up to 60 s: a first launch of an unsigned app is slow while macOS checks it) until the port answers, then opens the page. Downloads (zips, exports) are saved to ~/Downloads (`on_download`, never over a file); one copy runs at a time (single-instance); the window's buttons sit over the top bar (`body.app`, `data-tauri-drag-region`); the server exits when the app is gone (`watch_app`). The page detects the app (`window.__TAURI__`): Connect Krea opens the sign-in in the usual browser (`opener`), and **updates**: 4 s after opening it asks `latest.json` on GitHub (`checkForUpdate`, the updater plugin, signed with the key in ~/.tauri/phosphene.key, its public half in tauri.conf.json); "Restart to update" installs and relaunches (`installUpdate`). Releases go to a PUBLIC repository that holds only the app (thelau/phosphene-releases): `npm run release 0.1.1` (`scripts/release.sh`: versions, `app/build.py`, `tauri build`, `latest.json`, `gh release create`). `app/build.py` gathers `app/build/resources`: the PyInstaller server, the built page and ffmpeg (imageio-ffmpeg's, self-contained); no project (the app is the tool, projects are documents: the DMG is ~51 MB). A first launch has no project: the server runs with an empty library (`apply_no_project`, refusing what needs a project with `no_project`), and the page opens as usual, empty (`showNoProject`: "No project" in the header, "No images yet" in the middle of Curate and "No images selected" in the middle of the timeline, no logo target (`body.no-project`, its buttons off), nothing to play (the play buttons are off and Space does nothing with no image: no film, no sound), AI re-order off under two images (`syncAiBtn`), the project menu's list starts at New project… and Import project…). There is no welcome screen or banner (removed on request: people are told to go to Settings): Generate opens what is missing instead, the project menu with no project, Settings on Connect Krea (`ensureKreaReady`) or the Kimi key (`ensureKimiReady`); New project needs the Kimi key (Kimi reads the mark and fills the form), so without it Settings opens on the key. `openSettingsOn` opens Settings and ignores the click that asked for it (`settingsOpenedAt` against the event's time: the click-outside rule closed it again on its way up). The window's buttons are centred in the 56 px top bar (`traffic_light_position` 20, 21; the bar starts at 96 px in the app, at 20 px in full screen where they hide: `syncFullscreen`, `body.fullscreen`). Import project… in the app opens the macOS file dialog (`chooseProjectFile`: `TAURI.dialog.open`, `dialog:allow-open` in the capability; WebKit there opens nothing for a hidden file field) and imports the file from where it is (`/api/project-import-path`). The header: the brand and the project on the left, Curate | Film centred, `?` (the keys panel) beside Settings on the right. The icon, the header mark, the favicon and the splash are Claude Design's Direction B, Landing (cut ticks spreading apart, the playhead in orange): `app/icon.svg`, rendered to `app/icon-source.png`, `npx tauri icon` makes `app/src-tauri/icons`. The direction field's placeholder gives the chosen territory's own subjects (`world_examples`: two of its applications, cut short). The AI critic boxes show the server's values on load: scoring on by default, auto-trash off (they showed unticked before, while the critic scored every image). Projects travel as **NAME.phos** files (`.phosphene` before 2026-10-27: still opened by the app, Import and a double-click): a zip (project.json with `"format": 1`, state.json, mark, guides, every image) under its own name so Finder and a double-click know it (Tauri `fileAssociations`; `RunEvent::Opened` hands the path to `/api/project-import-path`, queued while the server starts); renamed .zip it opens anywhere, so nothing is locked in; a file from a newer format asks to update the app first. Demo is sent as one (Export project…). Working on it: `npm run app:live` runs the server and Vite on the app's own data (~/Documents/Phosphene, Application Support) and opens the native window (WebKit, as the app), reloading with every change; `npm run app:build` makes the real app (never run both at once: two servers on the same projects). Apple silicon only (aarch64); unsigned (no Apple Developer account): the first open is right-click › Open. macOS 27 refuses stripped proc-macro dylibs: `[profile.release.build-override] strip = false` in Cargo.toml. Tested: the frozen server on a fresh Documents (sample copied, 135 images, the logo check the same as the repo's, an MP4 made with the bundled ffmpeg) and the page in Playwright's WebKit (WebGL stage, the offline sound render, no errors).

## Safety (from a review of the app branch)
- Image names become paths only through `plate_name` (server) and `_clean_state` (a received project's curation): a bare file name, never `../` or an absolute path, so Empty trash can never delete outside the project's plates (a crafted .phosphene listing `/Users/.../thesis.pdf` as trashed did, before).
- The server answers only requests to `localhost` / `127.0.0.1` by that name (`from_this_computer`: a domain pointed at 127.0.0.1, DNS rebinding, is refused) and takes commands (POST) only from its own page (an `Origin` that is not local is refused: another website cannot empty the trash or switch project). Clients with no Origin (the app shell, curl, tests) are local by construction.
- The static fallback serves only `/assets/` (the old plate URLs), never a dotfile: `studio/.secrets.json` and `.krea_auth.json` are not reachable.
- A damaged project never stops the server: `open_first_project` passes it over (the next project, else the first screen). Imports: numeric names are made text, Finder's `__MACOSX`/`._` entries are ignored, a damaged zip says so and leaves nothing behind, two imports at once cannot delete each other's folder. Switching project holds `STATE_LOCK`. Krea token refreshes are one at a time (`_REFRESH_LOCK`). In the app no folder is made inside Phosphene.app (it may run read-only from the DMG).
- The app's port is fixed (47615) when free: the Krea sign-in comes back to the same address and the page's remembered settings (tied to the address) survive a relaunch. The menu bar: About Phosphene (the icon, the version, one line on what it is: `AboutMetadata`), New Project ⌘N, Open Project File… ⌘O (the macOS file dialog), Export Project… ⌘E, Curate ⌘1, Film ⌘2, Settings ⌘,, the standard Edit menu (the page gets every shortcut first: its own ⌘Z / ⌘S / ⌘A are not doubled). Files opened from Finder are imported off the main thread.

## Secrets
- A key is checked when saved (`check_kimi_key`: each endpoint's `/models`): one that Kimi refuses everywhere is not kept (the page says Key refused and that keys start with sk-); the endpoint that took a key is remembered and tried first (`KIMI_ENDPOINT`, `kimi_endpoints`), so a call does not go round the others. The key field is a text field masked with `-webkit-text-security` (as a password field, macOS filled a saved password into it).
- The Kimi API key lives in `studio/.secrets.json` (gitignored) or `KIMI_API_KEY` / `MOONSHOT_API_KEY`. Never write it into `curation_state.json` or any committed file.

## Conventions
- Prompts must keep the logo at dead-center, 18% width, with no extra rings or duplicate logos.
- Brand palette: orange #EC540C, pink #F64570, blue #5D8FF4, oxblood #381313, ink #1A1A1A, cream #FEFFE7.
- Default image model is `google/nano-banana-pro`; other Krea models are built in `build_model_input`.
- Use `AGENTS.md` for agent instructions; do not add a `CLAUDE.md`.

## Roadmap
Done:
1. Taste loop (`studio/taste.py`): kept = liked, trashed = disliked (logo-QA auto-trash is tracked separately in `qa_failed`), liked/disliked brief injected into prompt generation, per-model scorecard in Settings, "Auto" model that exploits/explores by score. Added Ideogram 4.5, Luma UNI-1, Meta Muse, Runway Gen-4 (all take the logo guide image).
2. Diversity (`studio/diversity.py`): no fixed categories; each shot is a random combo of subject/material/setting/light/camera/logo/palette, recent values avoided, near-duplicate prompts dropped (Jaccard novelty).
3. Tempo: BPM slider + cuts-per-beat multiple in preview and export.

4. Player effects (`planAt` / `zoomScale` / `trailAlpha` in `studio/web/src/app.js`, drawn by `render.js`): Invert (every image followed by an inverted grey/colour copy, as in Soiltone) and Zoom (slow in/out inside each cut, as in Moverunion: measured ~0.15-0.45% zoom OUT over a 5-frame cut). **Trail** (Look card, 0-60%, off by default): after each cut the previous image, as it ended, lingers on top and fades over 4 whole frames (`trailAlpha`; the stage overlays `#stageGhost`, the export blends the frames). Both apply to preview and export (one renderer, render.js). **Colour follows the chords** (each chord of the Changes bringing a brand colour to the picture: first a light 16% mix, too weak to be useful; then the darks lifted to the chord's shade, or the inverted copy as the chord's duotone, too strong) was tried and removed by the user (reverted in one commit): the picture answering the music needs another idea.

5. Order (`studio/sequences.py`): one order of the selection, yours: drag to rearrange (each drag is an undo step). **AI re-order…** (`/api/order-ai`, a background job; `studio/editor.py` + `studio/features.py`: Kimi writes the edit brief from a contact sheet, a deterministic beam search orders by cut kind, flip / shape echo / colour hand-off, no three of a kind in a row, territory variety, an energy arc; "Best N" sets `cut_off`, so preview and export use the first N and the rest sit below a "left out" divider with "Include them all") rearranges it without asking; its summary shows in the status bar, and Undo (the toast, the button, Cmd+Z) puts the previous order and its cut back (`/api/sequence` action `restore`). Under the hood the server still keeps a manual and an AI sequence (`sequences.py`); the page shows the active one as the order. Restored and new images go to the end. While the AI works, the server (409) and the page lock everything that changes the selection, and it cannot start while images generate or an export runs. **Groups** (`studio/groups.py`, `/api/groups`, a chip row under the tabs that scrolls sideways (trackpad or wheel, `groupFade` masks the side with more, the chosen chip is centred by `revealGroupChip`, the pick bar sits right after a divider, never over the chips)): All, your groups (stored in `st['groups']`: named views, an image can be in several, the order stays the one order), then automatic ones from each image's look (`features.look`: warm / cold / mono, dark / bright, from the cached measurements; the server measures new plates in the background) and territories with 6+ images. The grid, the film, AI re-order (`files`: the group's images swap among their own places, `add_group_order`) and the export (`files`) follow the group chosen (`currentGroup`, remembered). Cmd/Ctrl-click (Shift for a range, Cmd+A for all, Esc to clear), or the round pick circle at a card's top-right (on hover; on every card while picking), picks cards: Add to group (or New group…), Remove from group; your group's ⋯ renames or deletes it; every change is an undo step. Best N is for All only. The order tools were judged too complex (Manual / AI switch, read-only AI order, "use as Manual"): this is the simplification the user asked for.

6. Cuts and music (`studio/web/src/drone.js`; the page plans every cut, `rhythmFor`). **The timeline is the rhythm control** (the user's design, after Claude Design boards in "Phosphene — Curate & Film"; there is no Rhythm card and no Flat / Variable switch): the **Tempo** (40-1200 BPM = 1500-50 ms a music cut, `BPM_RANGE` / `MS_RANGE`) is the speed of the whole film, and at most **one change of speed** (`changeParams`: `from` and `to`, shares of the film's music cuts (`nMusic`, so a point stays on its image while the speeds move), `end_ms`, and `curve` 0-1: 0 an even, geometric change, each cut a constant ratio of the one before, as the references slow down (Ecwora holds 3-frame cuts for ~45% of the clip, then eases to ~21 frames over its last ~12 cuts; Soiltone the same); 1 waits and then changes sharply, ease = u^(1+4·curve) in log ms; `msAtShare` / `baseStarts`, cut i taken at its middle, never under a frame). Before `from` the film holds the tempo (the change's Start IS the tempo), after `to` the end speed. A landing or a build-up is just where the points sit. The settings live in hidden inputs in `.rhythm-src` (`bpmInput`, `multSelect`, `rhythmSelect` flat / variable = no change / a change, `changeFrom`, `changeTo`, `endMsRange`, `curveVal`); settings and snapshots from before (Start, End, Change over, Change at) open as the same film (`migrateRhythm`). Random and the Types still describe a change as start / end / ramp cuts / at, written onto the timeline by `setChange` (curve 0, 0.15 or 0.3); the tempo lock keeps the tempo and adds no change. **Multiple** (picture cuts per music cut) only changes the pictures: the page keeps two timelines in frames, the BASE the music follows and the PICTURE (`subdivideStarts`: the picture's k-th cut starts where base position k / multiple falls); the drone's pump, clicks, hits and arpeggio steps are on the base cuts, so a ×4 only cuts the pictures four times faster. The check **Also changes the music** (`followCuts`, off by default) puts the music's cuts on every picture cut instead. The server does not plan the rhythm any more: the page sends every frame and `frames`, plus `bpm`, `multiple`, `rhythm` and `end_ms` for the file's name (`-136bpm-x4-` or `-var441to900ms-`); `cutplan.py` is gone (the page's planning has its own tests). The sound speeds up and slows down with the base (variable) cuts. ## Picture renderer (studio/web/src/render.js)
One engine for the picture, as `drone.js` is for the sound (merged from the `webgl-renderer` branch after the user judged it): a WebGL2 renderer (`window.Render.create(canvas)`, `draw({ cur, ghost })`, `loadImage`) draws the stage on `#stageCanvas` (`initGl` / `paintGl`; `applyFx`, `drawTrail` and `clearFx` set `glLook`; the page still chooses which image shows when, and `#stageImg` / `#stageGhost` only feed it, hidden by `body.gl`). The export draws every frame with the same renderer at 1080 × 1920 from the full-size plates (`exportFrames`: frame f shows the clip at f + 0.5), JPEG 0.92, and sends them to `POST /api/export-frame?i=` (frame 0 starts a new set; a held run goes as one request, `&same=k&to=j`, after frame k arrived, stored as hard links so a long film takes no room; kept in `studio/.export/frames`, at most `EXPORT_FRAMES_MAX`); `/api/export-video` with `frames: N` checks every frame is there and only encodes. The server no longer draws frames or plans the rhythm (Pillow's `write_export_frames` and `cutplan.py` are gone). The shader uses the old export's numbers (grey = 1 - Pillow's 601 luma, the trail a plain mix, zoom a crop of the centre 1/scale, images cover the frame, no colour management); e2e tests read the renderer's pixels and decode the exported frames (plates, inverted copies, the trail's fade). ## Sound engine performance (studio/web/src/drone.js)
The live drone must never make the page janky. What keeps it cheap, and what tests guard (`studio/tests/e2e/drone.e2e.test.cjs`): cut-time events, hits and arpeggio notes are scheduled ~0.8 s ahead (`advance`, ticked every 90 ms), not for the whole clip; the arpeggio and each hit type are fixed voices retriggered by automation (no node per note); the reverb convolver is shared across swaps (loading its impulse response is the costliest step); noise and room sample data are made once per sample rate and shared by every context; settings changes are coalesced into one swap per ~120 ms, a swap whose only difference is where the clip ends (the Multiple) is skipped, and the exact loudness is measured when the page is idle. A new sound starts a moment ahead (the time a build takes), and its fade-in and the old sound's fade-out are timed from that instant: a fade timed before the build made every swap enter with a step. The room's impulse is noise band-limited to 150-900 Hz: low-passed noise alone drifts, and for some seeds made the room a strong boost near 100 Hz that swamped the sub (a test renders 20 seeds with a big room). Measured on a 300-cut fast clip with every layer on: a swap ~12 ms, longest main-thread block ~45 ms (it was 675 ms). `renderExport` / `level` / `Live` accept any numbers (empty or one-cut timelines, NaN, huge offsets) without throwing.
