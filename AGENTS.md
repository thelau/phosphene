# AGENTS.md

**Phosphene**: a logo-animation film generator (the name since 2026-10-26; it was "Demo Studio", and it is meant to go beyond the Demo logo). Demo 9:16 match-cut film project. Every shot places the circular orbital logo at exact dead-center (50%, 50%), 18% of frame width, in a different material/scene.

## Layout
- `studio/server.py` — the API server (port 8765, `PORT` env to change): JSON API, plates and exported video. It also serves the built page from `studio/web/dist` if `npm run build` was run.
- `studio/web/` — the frontend (Vite, vanilla JS): `index.html` (markup), `src/app.js`, `src/style.css`, `vite.config.js` (proxies `/api`, `/assets`, `/outputs` to :8765). Inline `onclick=` handlers need the function exported at the bottom of `app.js` (a test checks this).
- `studio/krea_mcp_client.py` — Krea image generation over MCP (`https://api.krea.ai/mcp`). OAuth token is read from `~/.local/share/opencode/mcp-auth.json`.
- `studio/qa_engine.py` — logo QA on generated plates (needs `demo-info/design-system/logo-cream.png`). `demo-info/` also holds the design-system PDFs and the playbook: reference, not read by code.
- `studio/chapters.py` (territories), `diversity.py` (random axes), `taste.py` (learning from kept/trashed), `critic.py` (optional AI scoring, off by default), `cutplan.py` (preview/export frame plan, invert, zoom), `web/src/drone.js` (the synthesized drone, WebAudio), `sequences.py` (Manual/AI orders), `editor.py` + `features.py` (AI ordering), `bench.py` (scripted generation runs, optional).
- `studio/gen_log.py` — the written record of what the server did (`studio/generation_log.jsonl`, gitignored, rotates at 5 MB): server starts, Kimi batches, every image (all retries, logo check, seconds), AI orders, exports, deletions. Read it with `npm run log` (or `python3 studio/gen_log.py --failures`), or `GET /api/log`. An `image_start` with no result followed by a `server_start` means a restart cut the image short.
- `studio/curation_state.json` — approvals, trash, order, titles, prompts, per-plate model. Committed on purpose: it is the selection history.
- `assets/ai-plates/` — generated plates (committed). `outputs/*.mp4` is gitignored.

## Run
```fish
npm install        # once
npm run dev        # API with auto-restart (studio/dev.py) + Vite with hot reload -> http://localhost:5173
```
Separately: `npm run api` (backend only, restarts when `studio/*.py` changes, the page reloads itself) and `npm run web` (Vite only). `npm run build` writes `studio/web/dist` and the backend then serves the page at :8765. Needs Python 3 with Pillow (`pip3 install -r requirements.txt`), ffmpeg at `/opt/homebrew/bin/ffmpeg`, Node 20+. The user runs these themselves; do not start or kill their server unless asked. Do not restart the API mid-generation.

## Secrets
- The Kimi API key lives in `studio/.secrets.json` (gitignored) or `KIMI_API_KEY` / `MOONSHOT_API_KEY`. Never write it into `curation_state.json` or any committed file.

## Conventions
- Prompts must keep the logo at dead-center, 18% width, with no extra rings or duplicate logos.
- Brand palette: orange #EC540C, pink #F64570, blue #5D8FF4, oxblood #381313, ink #1A1A1A, cream #FEFFE7.
- Default image model is `google/nano-banana-pro`; other Krea models are built in `build_model_input`.
- Use `AGENTS.md` for agent instructions; do not add a `CLAUDE.md`.

Under the film strip, the **rhythm strip** (`rhythmStripModel` / `renderRhythmStrip`) draws the whole film in time from `rhythmFor`, so it cannot disagree with the player or the export: a tick per picture cut, the speed line (high = fast), the Landing / Build-up band with Start and End marked, the music's cuts as blue dots, a seconds axis, the playhead; a click jumps there (`rhythmStripClick`). The inner point (where a landing begins, where a build-up ends) drags sideways to set Change over (`rampAt` solves for the value that puts the point under the pointer, since the change moves the film's length); the point at the clip's edge does not drag. The Export line estimates how long an export takes from the last five on this computer (`exportEstimate`). ## Roadmap
Done:
1. Taste loop (`studio/taste.py`): kept = liked, trashed = disliked (logo-QA auto-trash is tracked separately in `qa_failed`), liked/disliked brief injected into prompt generation, per-model scorecard in Settings, "Auto" model that exploits/explores by score. Added Ideogram 4.5, Luma UNI-1, Meta Muse, Runway Gen-4 (all take the logo guide image).
2. Diversity (`studio/diversity.py`): no fixed categories; each shot is a random combo of subject/material/setting/light/camera/logo/palette, recent values avoided, near-duplicate prompts dropped (Jaccard novelty).
3. Tempo: BPM slider + cuts-per-beat multiple in preview and export.

4. Player effects (`studio/cutplan.py`, mirrored by `planAt`/`zoomScale` in `studio/web/src/app.js`; tests share vectors): Invert (every image followed by an inverted grey/colour copy, as in Soiltone) and Zoom (slow in/out inside each cut, as in Moverunion: measured ~0.15-0.45% zoom OUT over a 5-frame cut). **Trail** (Look card, 0-60%, off by default): after each cut the previous image, as it ended, lingers on top and fades over 4 whole frames (`cutplan.trail_alpha` / `trailAlpha`, shared vectors; the stage overlays `#stageGhost`, the export blends the frames). Both apply to preview and export. **Colour follows the chords** (a check in the Look card, off by default, a trial to keep or kill): with chord Changes on, each chord brings a brand colour (`cutplan.CHORD_TINTS`: VII and iv blue, VI and III orange, v pink, the home chord none), switching on the cut where the chord changes. Two looks (a flat 16% mix over the picture came first and was too weak): Invert off, **the grade**, the darks lift to the chord's shade (`cutplan.GRADE`, the colour at 40%; out = max(picture, shade), the page's `#stageTint` with mix-blend-mode lighten), highlights and the logo untouched; Invert on, **the twin**, the inverted copy becomes the chord's duotone (`cutplan.duotone`: the chord colour in the original's darks, oxblood or ink in its lights, `DUO_SHADOW`; the page's SVG filters `#duo-xxxxxx` in index.html, tests check the numbers match), the original untouched. The page sends where each chord starts (`tints`, `tintSegments` / `clean_tints`); the timing comes from the sound engine (`Drone.chordAt`), one source of truth; Random ticks it 60% of the time when it brings chord changes.

5. Order (`studio/sequences.py`): one order of the selection, yours: drag to rearrange (each drag is an undo step). **AI re-order…** (`/api/order-ai`, a background job; `studio/editor.py` + `studio/features.py`: Kimi writes the edit brief from a contact sheet, a deterministic beam search orders by cut kind, flip / shape echo / colour hand-off, no three of a kind in a row, territory variety, an energy arc; "Best N" sets `cut_off`, so preview and export use the first N and the rest sit below a "left out" divider with "Include them all") rearranges it without asking; its summary shows in the status bar, and Undo (the toast, the button, Cmd+Z) puts the previous order and its cut back (`/api/sequence` action `restore`). Under the hood the server still keeps a manual and an AI sequence (`sequences.py`); the page shows the active one as the order. Restored and new images go to the end. While the AI works, the server (409) and the page lock everything that changes the selection, and it cannot start while images generate or an export runs. **Groups** (`studio/groups.py`, `/api/groups`, a chip row under the tabs that scrolls sideways (trackpad or wheel, `groupFade` masks the side with more, the chosen chip is centred by `revealGroupChip`, the pick bar sits right after a divider, never over the chips)): All, your groups (stored in `st['groups']`: named views, an image can be in several, the order stays the one order), then automatic ones from each image's look (`features.look`: warm / cold / mono, dark / bright, from the cached measurements; the server measures new plates in the background) and territories with 6+ images. The grid, the film, AI re-order (`files`: the group's images swap among their own places, `add_group_order`) and the export (`files`) follow the group chosen (`currentGroup`, remembered). Cmd/Ctrl-click (Shift for a range, Cmd+A for all, Esc to clear), or the round pick circle at a card's top-right (on hover; on every card while picking), picks cards: Add to group (or New group…), Remove from group; your group's ⋯ renames or deletes it; every change is an undo step. Best N is for All only. The order tools were judged too complex (Manual / AI switch, read-only AI order, "use as Manual"): this is the simplification the user asked for.

6. Cuts and music (`studio/web/src/drone.js`, mirrored in the page by `cutAt`/`planAt`). Film's Rhythm card: **Speed** is **Flat** (every cut the same length from Tempo and Multiple, as in Helione and Moverunion) or **Variable** (as in the references: Ecwora holds 3-frame cuts for ~45% of the clip, then eases to ~21 frames over its last ~12 cuts; Soiltone the same. Start length, End length, **Change over** N cuts (its slider range is the number of cuts of the selection, so it follows added and removed images and invert pairs) and **Change at** the end (a landing, default) or the start (a build-up). The change is geometric, each cut a constant ratio of the one before; `cutplan.variable_timeline` / `variableStarts` (shared vectors), 50-1500 ms at 30 fps, timeline in frames with frames_per_cut = 1; export body `rhythm: "variable", start_ms, end_ms, ramp, at`; file name `-var100to600ms-`). The landing lasts the same however many images there are. Flat is the special case start == end. **Multiple** (picture cuts per beat, or per cut of the variable run) only changes the pictures: the page keeps two timelines in frames, the BASE the music follows (the beat grid at the Tempo slider, 1-500 BPM, or the variable run) and the PICTURE (`cutplan.rhythm_timeline` / `rhythmFor`, `subdivide`: the picture's k-th cut starts where base position k / multiple falls); the drone's pump, clicks, hits and arpeggio steps are on the base cuts, so a ×4 only cuts the pictures four times faster. The check **The Multiple also changes the music** (`followCuts`, off by default) puts the music's cuts on every picture cut instead (then the pump, hits and arpeggio follow the Multiple too). Export body: `bpm`, `multiple`, `rhythm`, ...  The sound speeds up and slows down with the base (variable) cuts. The Sound card's **Source** is Off or **Synthesized** (`drone.js`, WebAudio, no server): one stereo drone modelled on measurements of the reference clips (they are not drum tracks but a continuous dark sub-bass bed: 43-54 Hz carries 65-90% of the energy, almost nothing above 2 kHz; the Soiltone/Ecwora one is ~54 Hz sub, unison saw pad, tonal 215-516 Hz cluster, wide, in a reverb room). Settings 0-100, all on the panel: Pulse (the bed pumps on each cut), Low end, Power (unison + saturation), Space (room), Bright, Width, Pitch (root 38-71 Hz), Chord (dark cluster = the measured one, open fifth, minor, suspended), **Changes** (`PROGRESSIONS`, off by default: the bed moves through degrees of the minor key every 2/4/8/16 music cuts and comes round, Descend i-VII-VI-V, Lift i-III-iv-III, Pendulum i-v, Wander a seeded walk in the key; one ConstantSource in cents into the bed's oscillators' detune, a short glide; the arpeggio and hits stay in the home key, a melody over a moving bass; with changes on the chord sheds its third (minor plays suspended, the dark cluster an open fifth) so every chord stays in key; Random turns them on a third of the time with each chord 1-4 s (so 2 and 4 cuts come up on faster films too), `rollChanges`; an e2e test checks the bass lands on each degree), Movement (LFO speed), Echo (dark feedback echo timed to the cuts). Layers, all off by default and all randomised by Random sound: **Wash / Ring / Shimmer** textures, **Choir** (low saw voices on two chord tones through drifting vowel formants) and **Industrial** (a metal noise burst on every other cut, more saturation and air): two layers over the drone in the Texture tab. Random adds one now and then, never both, with taste: Random sound gives the choir 30% of draws on slow cuts (3 a second or fewer) and 10% on faster ones, Industrial 5% and 20%; never voices over a strobe (more than 5 cuts a second); a Type only its own (`layer` in `CHARACTERS`, with `odds`: 50% in Float, Drift and Breath, 40% Machine, 30% Landing and Build, 25% Pulse and Strobe), and gives it room (one texture beside it; no busy arpeggio under the choir; no hits with Industrial). Separate voices (Glass, Industrial, Choir, Pure tone) were tried and rejected by ear: the drone is the sound. **Sub** and **Pad** waves (sine/triangle/square; saw/square/triangle/pulse), **Hits** (Thud, Knock, Metal, Noise burst; Impact; on every cut / every 2nd / every 4th / uneven accents), an **Arpeggio** (a short seeded pattern of 4/6/8/16 notes, with a **Mood** (`ARP_MOODS`, six, judged by the user's ear): Pluck = the first one, chord tones in a random walk; Dark (phrygian, low, falling); Phase (two loops of the same notes, one a note longer (`phaseLoop`), one on each side, drifting apart and back: Reich / Barbieri); Sweep (a short walk while the filter opens and shuts over ~7 s, resonant); Mutate (one note changes each round, a Turing Machine); Accumulate (2 notes, then 3, ... then the whole pattern, over again); Mellow, Beautiful, Tender and Ratchet were tried and removed by ear; all on Pluck's modular patch (two detuned saws, a resonant low-pass that snaps shut: the user wants the Caterina Barbieri modular sound throughout; soft sine/triangle presets were tried and rejected), each mood only its own scale, register, shape, filter range, resonance and note length, two voices taking turns so notes ring on; levels balanced so each sits in the bed (an e2e test renders all six); Random keeps Phase unhurried on fast cuts, and the choir only with Phase, Sweep or Mutate; 1 per 2 cuts up to 4 per cut, so it speeds up and slows down with the cuts) a **Bassline** (`BASS_PATTERNS`: Pulse, Octave, Fifths, Gallop; a plucked saw + square an octave over the sub through a resonant low-pass, 1/2/4 notes a music cut; root, fifth and octave only so it stays in key; it follows the chord changes), an **Arrangement** (`ARRANGEMENTS`: Off; Build-up, the arpeggio, then the bassline, then the hits come in and the ending strips back; Sections, sparse and full by turns every 8 music cuts (`SECTIONS`); Follows the speed, fuller while the cuts are fast; each layer has its own level, `arr`, automated over the film; the bed always plays; Random draws both per Type (`shape` in `CHARACTERS`, `rollShape`) and makes sure an arrangement has at least two layers to move; e2e tests measure the bass and the arrangement), and **Dynamics** (an arc on the notes, never the volume: Rise climbs and sharpens over the whole clip whatever the speed, Fall sinks and softens over it, Follows the speed is higher and brighter while the cuts are fast and does nothing at a flat speed; it moves the pitch, length and brightness of the hits and arpeggio notes, and the chord cluster a few semitones). The references have no hits locked to the cuts (measured: a bed with a 2.5-9 Hz tremolo and a level that decays after each cut start), so hits and the arpeggio are creative additions, not copies. **Random** (the bar at the top of the inspector, `randomAll`) rolls rhythm, look, sound and the music check together inside the **Type** (`CHARACTERS`: Landing, Build, Drift, Pulse, Breath, Strobe, Float, Machine, each a set of tighter ranges modelled on the references; **Any** = anything inside the safe ranges; choosing a type rolls at once; Undo does not change the type), then matches the sound to the speed (`matchSoundToSpeed`) and applies `soundRules` (two textures at most, an arpeggio on properly or off, no Follows the speed on a flat speed, bright held back from ring and shimmer, no echo on very fast cuts, hits on every fast cut and 4 notes a cut never together). The Sound column also has **Random sound** (`randomMusic`), a new sound for the same cut; there are no other dice (one feature, one control). **Undo** steps back from the last random (`undoRandom`). **Random sound** (`randomMusic`, ranges in `RANDOM_RANGES`) draws every setting inside ranges that keep it a dark, heavy drone; an e2e test renders random draws through the real engine and checks they stay sub-heavy and level. **Sonority** (from the user's playlist, melodic techno / electro / IDM, taken as instrumental timbre only: a drum machine was built and rejected, reverted in `7424e21`): a **Pad** (Tone tab: two detuned saws a note, a chorus each side, a slow filter; it voices real chords in the natural minor on each chord of the changes, `padChord`: i m7, VII 7, VI maj7, v m7, III maj7, iv m7, root / fifth / seventh / third an octave up, so the changes become harmony and not a shifted drone); an **Acid** arpeggio mood (the same saws, low, resonance 13, accents and slides fixed per step, saturation after the filter); **Tape** (Texture tab: wow and flutter on a modulated delay, saturation, a lowpass from 14 to 4.5 kHz, a little dust) on the way out. The user said no pad takeover and no distortion wall: the pad sits under the drone (an e2e test: even at 100, under full tape, the sub stays dominant), tape is warmth (gentle saturation) not drive, Acid's drive is light. Random brings pad and tape by Type (`shape.pad`, `shape.tape`), modest (pad ≤45, tape ≤45; together both low or no tape), Acid in Pulse, Machine and Strobe; under the choir no Acid and a quieter pad. An e2e test checks the pad's voicing (VI sounds its major third) and that all three keep the level. A **Rise** (a white-noise swell into the film's moment, then an impact) was built and removed: the user found the swoosh crap. A **Stutter** (a slice of the whole sound looped on phrase ends) was also built and removed by ear. **Polyrhythm**: arpeggio speeds 3 notes per 2 cuts and 3 per 4 (`ARP_PER_CUT` 1.5 / 0.75; `notesIn`: note k sits at k / rate cuts, so any rate stays in phase from any offset). Random: a polyrhythm 15% of the time. The drone plays live in the page: sliders and tempo changes swap the sound in ~40 ms from where the picture is (no render, no spinner). The export renders the same graph offline in the page (`OfflineAudioContext`, ~0.5 s), leveled and glued, and uploads the WAV (`POST /api/export-audio`, kept in `studio/.export/`) just before `/api/export-video` with `music: "synth"`; ffmpeg muxes it as AAC. Preview and export are one engine; an e2e test measures the offline render against the reference numbers (sub 40-65 Hz, >60% below 80 Hz, <2% above 2 kHz, RMS 0.17). The sound has not been judged by ear by the agent. A user's own track was built (hit/note/beat analysis with numpy, cuts on the music) and removed on purpose: the user mixes a silent export with their track in a video editor. Zoom stays per cut (a continuous zoom across an image and its inverted copy was tried and rejected). Plates are also served resized (`/api/thumb?f=&w=360|540`, cached in `studio/.thumbs/`, gitignored): the grid and the preview use them, not the full-size files.

Quality reference: `inspiration/soiltone-inspo.mp4` — 8s, ~48 cuts, each scene shown as a color/mono twin pair, one hero subject, logo crisp at dead-center. Quality bar lives in `QUALITY_BAR` in `server.py`.

## Sound engine performance (studio/web/src/drone.js)
The live drone must never make the page janky. What keeps it cheap, and what tests guard (`studio/tests/e2e/drone.e2e.test.cjs`): cut-time events, hits and arpeggio notes are scheduled ~0.8 s ahead (`advance`, ticked every 90 ms), not for the whole clip; the arpeggio and each hit type are fixed voices retriggered by automation (no node per note); the reverb convolver is shared across swaps (loading its impulse response is the costliest step); noise and room sample data are made once per sample rate and shared by every context; settings changes are coalesced into one swap per ~120 ms, a swap whose only difference is where the clip ends (the Multiple) is skipped, and the exact loudness is measured when the page is idle. A new sound starts a moment ahead (the time a build takes), and its fade-in and the old sound's fade-out are timed from that instant: a fade timed before the build made every swap enter with a step. The room's impulse is noise band-limited to 150-900 Hz: low-passed noise alone drifts, and for some seeds made the room a strong boost near 100 Hz that swamped the sub (a test renders 20 seeds with a big room). Measured on a 300-cut fast clip with every layer on: a swap ~12 ms, longest main-thread block ~45 ms (it was 675 ms). `renderExport` / `level` / `Live` accept any numbers (empty or one-cut timelines, NaN, huge offsets) without throwing.
