# AGENTS.md

Demo 9:16 match-cut film project. Every shot places the circular orbital logo at exact dead-center (50%, 50%), 18% of frame width, in a different material/scene.

## Layout
- `studio/server.py` — the API server (port 8765, `PORT` env to change): JSON API, plates and exported video. It also serves the built page from `studio/web/dist` if `npm run build` was run.
- `studio/web/` — the frontend (Vite, vanilla JS): `index.html` (markup), `src/app.js`, `src/style.css`, `vite.config.js` (proxies `/api`, `/assets`, `/outputs` to :8765). Inline `onclick=` handlers need the function exported at the bottom of `app.js` (a test checks this).
- `studio/krea_mcp_client.py` — Krea image generation over MCP (`https://api.krea.ai/mcp`). OAuth token is read from `~/.local/share/opencode/mcp-auth.json`.
- `studio/qa_engine.py` — logo QA on generated plates (needs `demo-info/design-system/logo-cream.png`). `demo-info/` also holds the design-system PDFs and the playbook: reference, not read by code.
- `studio/chapters.py` (territories), `diversity.py` (random axes), `taste.py` (learning from kept/trashed), `critic.py` (optional AI scoring, off by default), `cutplan.py` (preview/export frame plan, invert, zoom), `web/src/drone.js` (the synthesized drone, WebAudio), `sequences.py` (Manual/AI orders), `editor.py` + `features.py` (AI ordering), `bench.py` (scripted generation runs, optional).
- `studio/gen_log.py` — the written record of what the server did (`studio/generation_log.jsonl`, gitignored, rotates at 5 MB): server starts, Kimi batches, every image (all retries, logo check, seconds), AI orders, exports, deletions. Read it with `npm run log` (or `python3 studio/gen_log.py --failures`), or `GET /api/log`. An `image_start` with no result followed by a `server_start` means a restart cut the image short.
- `studio/curation_state.json` — approvals, trash, order, titles, prompts, per-plate model. Committed on purpose: it is the selection history.
- `assets/ai-plates/` — generated plates (committed). `outputs/*.mp4` is gitignored.

## Run
```fish
npm install        # once
npm run dev        # API with auto-restart (studio/dev.py) + Vite with hot reload -> http://localhost:5173
```
Separately: `npm run api` (backend only, restarts when `studio/*.py` changes, the page reloads itself) and `npm run web` (Vite only). `npm run build` writes `studio/web/dist` and the backend then serves the page at :8765. Needs Python 3 with Pillow (`pip3 install -r requirements.txt`), ffmpeg at `/opt/homebrew/bin/ffmpeg`, Node 20+. The user runs these themselves; do not start or kill their server unless asked. Do not restart the API mid-generation.

## Secrets
- The Kimi API key lives in `studio/.secrets.json` (gitignored) or `KIMI_API_KEY` / `MOONSHOT_API_KEY`. Never write it into `curation_state.json` or any committed file.

## Conventions
- Prompts must keep the logo at dead-center, 18% width, with no extra rings or duplicate logos.
- Brand palette: orange #EC540C, pink #F64570, blue #5D8FF4, oxblood #381313, ink #1A1A1A, cream #FEFFE7.
- Default image model is `google/nano-banana-pro`; other Krea models are built in `build_model_input`.
- Use `AGENTS.md` for agent instructions; do not add a `CLAUDE.md`.

## Two modes (studio/web)
The page has two modes, switched at the top (`setMode`, remembered in localStorage `studioMode`; **Tab** switches and **Space** plays, except while typing in a field): **Curate** (generation row; Selection / Trash, Manual / AI orders and Order with AI, a hint and the S / M / L thumbnail size; a lock banner while the AI orders; numbered cards with the title under the image, hover actions (drag, info, trash with an Undo toast that puts the image back in place), pick boxes and Restore in the Trash, New on images that arrived since the page opened, placeholders for the images still generating; a floating film preview (the same stage element, moved there by `setMode`, so one player and one sound) that hides to a pill and opens Film) and **Film** (the 9:16 preview; transport with play, restart, logo target and timecode (no sound switch there: Source is the one; the user asked for no duplicate controls); the timeline panel with the film strip, the edit as thumbnails, click to jump (`jumpToPlate`), Trash for the image on screen with an Undo toast; the inspector, 600 px: Type, Random and Undo across its top, then two columns that scroll on their own, Rhythm and Look on the left, Sound on the right in four groups Bed / Tone / Texture / Notes, so Flat / Variable never moves the sound; Export pinned at its foot with idle / busy / ready states; a test checks no label is cut off at 1280 × 720). Speed, Change at, Invert, Zoom and Source are segmented buttons built from hidden `<select class="seg-src">` that stay the source of truth (`buildSegs` / `syncSegs`); tests drive them with `choose(id, value)` and switch modes with `film()` / `curate()` (e2e harness). Under the film strip, the **rhythm strip** (`rhythmStripModel` / `renderRhythmStrip`) draws the whole film in time from `rhythmFor`, so it cannot disagree with the player or the export: a tick per picture cut, the speed line (high = fast), the Landing / Build-up band with Start and End marked, the music's cuts as blue dots, a seconds axis, the playhead; a click jumps there (`rhythmStripClick`). It is display only (dragging was judged not worth it next to the sliders). Play carries on from the playhead; Restart goes back to the start; the drone follows jumps (`Live.seek`). Below 1200 × 640 the page asks for a bigger window (a 13" laptop fits). Fonts (Schibsted Grotesk, JetBrains Mono) are bundled in `studio/web/src/fonts/`, so nothing loads from the network. The design spec is the Claude Design artifact "Demo Studio — Curate & Film".

## Roadmap
Done:
1. Taste loop (`studio/taste.py`): kept = liked, trashed = disliked (logo-QA auto-trash is tracked separately in `qa_failed`), liked/disliked brief injected into prompt generation, per-model scorecard in Settings, "Auto" model that exploits/explores by score. Added Ideogram 4.5, Luma UNI-1, Meta Muse, Runway Gen-4 (all take the logo guide image).
2. Diversity (`studio/diversity.py`): no fixed categories; each shot is a random combo of subject/material/setting/light/camera/logo/palette, recent values avoided, near-duplicate prompts dropped (Jaccard novelty).
3. Tempo: BPM slider + cuts-per-beat multiple in preview and export.

4. Player effects (`studio/cutplan.py`, mirrored by `planAt`/`zoomScale` in `studio/web/src/app.js`; tests share vectors): Invert (every image followed by an inverted grey/colour copy, as in Soiltone) and Zoom (slow in/out inside each cut, as in Moverunion: measured ~0.15-0.45% zoom OUT over a 5-frame cut). Both apply to preview and export.

5. Orders (`studio/sequences.py`): exactly two orders of the selection, **Manual** (always there) and **AI** (made by Order with AI; redoing replaces it, after a confirmation). Both are editable by dragging; the AI order remembers its original so "↺ Back to the AI's order" resets it. Switching loses nothing; the player follows the switch. Restored/new images go to the end of both. While the AI orders, the server (409) and the page lock everything that changes the selection, and ordering cannot start while images generate. "Use as my Manual order…" (with confirmation) copies the AI order, cut included, over Manual and keeps the AI order; the divider's "Include them all" clears a best-N cut. AI ordering (`studio/editor.py` + `studio/features.py`): Kimi (vision, contact sheet) writes the edit brief (opener, closer, peaks, weights), a deterministic beam search orders by cut kind (flip / shape echo / colour hand-off), no three of a kind in a row, territory variety, an energy arc; "Best N" sets `cut_off` (preview and export use only the first N; the rest sit below a "left out" divider). Runs as a background job (`/api/order-ai`, `/api/order-ai-status`).

6. Cuts and music (`studio/web/src/drone.js`, mirrored in the page by `cutAt`/`planAt`). Film's Rhythm card: **Speed** is **Flat** (every cut the same length from Tempo and Multiple, as in Helione and Moverunion) or **Variable** (as in the references: Ecwora holds 3-frame cuts for ~45% of the clip, then eases to ~21 frames over its last ~12 cuts; Soiltone the same. Start length, End length, **Change over** N cuts (its slider range is the number of cuts of the selection, so it follows added and removed images and invert pairs) and **Change at** the end (a landing, default) or the start (a build-up). The change is geometric, each cut a constant ratio of the one before; `cutplan.variable_timeline` / `variableStarts` (shared vectors), 50-1500 ms at 30 fps, timeline in frames with frames_per_cut = 1; export body `rhythm: "variable", start_ms, end_ms, ramp, at`; file name `-var100to600ms-`). The landing lasts the same however many images there are. Flat is the special case start == end. **Multiple** (picture cuts per beat, or per cut of the variable run) only changes the pictures: the page keeps two timelines in frames, the BASE the music follows (the beat grid at the Tempo slider, 1-500 BPM, or the variable run) and the PICTURE (`cutplan.rhythm_timeline` / `rhythmFor`, `subdivide`: the picture's k-th cut starts where base position k / multiple falls); the drone's pump, clicks, hits and arpeggio steps are on the base cuts, so a ×4 only cuts the pictures four times faster. The check **The Multiple also changes the music** (`followCuts`, off by default) puts the music's cuts on every picture cut instead (then the pump, hits and arpeggio follow the Multiple too). Export body: `bpm`, `multiple`, `rhythm`, ...  The sound speeds up and slows down with the base (variable) cuts. The Sound card's **Source** is Off or **Synthesized** (`drone.js`, WebAudio, no server): one stereo drone modelled on measurements of the reference clips (they are not drum tracks but a continuous dark sub-bass bed: 43-54 Hz carries 65-90% of the energy, almost nothing above 2 kHz; the Soiltone/Ecwora one is ~54 Hz sub, unison saw pad, tonal 215-516 Hz cluster, wide, in a reverb room). Settings 0-100, all on the panel: Pulse (the bed pumps on each cut), Low end, Power (unison + saturation), Space (room), Bright, Width, Pitch (root 38-71 Hz), Chord (dark cluster = the measured one, open fifth, minor, suspended), Movement (LFO speed), Echo (dark feedback echo timed to the cuts). Layers, all off by default and all randomised by Random sound: **Wash / Ring / Shimmer** textures, **Sub** and **Pad** waves (sine/triangle/square; saw/square/triangle/pulse), **Hits** (Thud, Knock, Metal, Noise burst; Impact; on every cut / every 2nd / every 4th / uneven accents), an **Arpeggio** (a short seeded pattern of 4/6/8/16 plucked notes from the chord, 1 per 2 cuts up to 4 per cut, so it speeds up and slows down with the cuts) and **Dynamics** (an arc on the notes, never the volume: Rise climbs and sharpens over the whole clip whatever the speed, Fall sinks and softens over it, Follows the speed is higher and brighter while the cuts are fast and does nothing at a flat speed; it moves the pitch, length and brightness of the hits and arpeggio notes, and the chord cluster a few semitones). The references have no hits locked to the cuts (measured: a bed with a 2.5-9 Hz tremolo and a level that decays after each cut start), so hits and the arpeggio are creative additions, not copies. **Random** (the bar at the top of the inspector, `randomAll`) rolls rhythm, look, sound and the music check together inside the **Type** (`CHARACTERS`: Landing, Build, Drift, Pulse, Breath, Strobe, Float, Machine, each a set of tighter ranges modelled on the references; **Any** = anything inside the safe ranges; choosing a type rolls at once; Undo does not change the type), then matches the sound to the speed (`matchSoundToSpeed`) and applies `soundRules` (two textures at most, an arpeggio on properly or off, no Follows the speed on a flat speed, bright held back from ring and shimmer, no echo on very fast cuts, hits on every fast cut and 4 notes a cut never together). The Sound column also has **Random sound** (`randomMusic`), a new sound for the same cut; there are no other dice (one feature, one control). **Undo** steps back from the last random (`undoRandom`). **Random sound** (`randomMusic`, ranges in `RANDOM_RANGES`) draws every setting inside ranges that keep it a dark, heavy drone; an e2e test renders random draws through the real engine and checks they stay sub-heavy and level. The drone plays live in the page: sliders and tempo changes swap the sound in ~40 ms from where the picture is (no render, no spinner). The export renders the same graph offline in the page (`OfflineAudioContext`, ~0.5 s), leveled and glued, and uploads the WAV (`POST /api/export-audio`, kept in `studio/.export/`) just before `/api/export-video` with `music: "synth"`; ffmpeg muxes it as AAC. Preview and export are one engine; an e2e test measures the offline render against the reference numbers (sub 40-65 Hz, >60% below 80 Hz, <2% above 2 kHz, RMS 0.17). The sound has not been judged by ear by the agent. A user's own track was built (hit/note/beat analysis with numpy, cuts on the music) and removed on purpose: the user mixes a silent export with their track in a video editor. Zoom stays per cut (a continuous zoom across an image and its inverted copy was tried and rejected). Plates are also served resized (`/api/thumb?f=&w=360|540`, cached in `studio/.thumbs/`, gitignored): the grid and the preview use them, not the full-size files.

Quality reference: `inspiration/soiltone-inspo.mp4` — 8s, ~48 cuts, each scene shown as a color/mono twin pair, one hero subject, logo crisp at dead-center. Quality bar lives in `QUALITY_BAR` in `server.py`.

Caveat: the 223 plates trashed before `qa_failed` existed can't be told apart (manual vs QA), so older model scores are noisy.

## Sound engine performance (studio/web/src/drone.js)
The live drone must never make the page janky. What keeps it cheap, and what tests guard (`studio/tests/e2e/drone.e2e.test.cjs`): cut-time events, hits and arpeggio notes are scheduled ~0.8 s ahead (`advance`, ticked every 90 ms), not for the whole clip; the arpeggio and each hit type are fixed voices retriggered by automation (no node per note); the reverb convolver is shared across swaps (loading its impulse response is the costliest step); noise and room sample data are made once per sample rate and shared by every context; settings changes are coalesced into one swap per ~120 ms, a swap whose only difference is where the clip ends (the Multiple) is skipped, and the exact loudness is measured when the page is idle. A new sound starts a moment ahead (the time a build takes), and its fade-in and the old sound's fade-out are timed from that instant: a fade timed before the build made every swap enter with a step. The room's impulse is noise band-limited to 150-900 Hz: low-passed noise alone drifts, and for some seeds made the room a strong boost near 100 Hz that swamped the sub (a test renders 20 seeds with a big room). Measured on a 300-cut fast clip with every layer on: a swap ~12 ms, longest main-thread block ~45 ms (it was 675 ms). `renderExport` / `level` / `Live` accept any numbers (empty or one-cut timelines, NaN, huge offsets) without throwing.
